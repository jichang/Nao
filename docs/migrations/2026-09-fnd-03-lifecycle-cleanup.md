# FND-03 lifecycle cleanup

This development-stage change intentionally breaks earlier persistence and API shapes in favor of explicit ownership and lifecycle contracts. Nao does not provide dual reads or an in-process migration path.

## Breaking changes

- `ExecutionRecord` now requires `Id`, `Owner`, and `TurnId`.
- `ExecutionJournal.MarkRevertedAsync` accepts the stable record ID.
- Execution journals use authenticated `execution-journal/<identity-sha256>` version-1 event streams with owner-free payloads.
- File execution journals use a versioned document with `schemaVersion = 1` and a `records` collection.
- Turn and feedback JSONL files accept typed lifecycle events only; raw record lines are unsupported.
- `MemoryStore.ClearAsync` was removed. `DeleteOwnerAsync` is the sole owner-wide deletion operation.
- `WorkingMemoryItem` has no execution or authorization field. Every operation accepts an opaque `WorkingMemoryAddress` combining `AuthorizationScope` and `ExecutionId`; capacity, pure reads, explicit attention, decay, pinning, rendering, and deletion are isolated by both. `ClearAsync` was replaced by counted `DeleteOwnerAsync` and `DeleteExpiredAsync` operations.
- Working-memory v1 events use `working/<identity-sha256>/<execution-id>.jsonl` files or equivalent ADO streams, with owner-free payloads containing the capacity/TTL/decay policy plus effective focus, decay, and unpin changes. `GetAsync` no longer boosts attention implicitly; use `FocusAsync`. Compute the identity key with `AuthorizationIdentity.storageKey`. Shared `working.jsonl` files and `working` ADO streams have no compatibility reader. Reset disposable state, or externally transform retained events using verified complete identity and execution ownership plus the original policy. Changing policy requires explicit external transformation or reset. Validate address isolation, expiry, focus, pinning, deletion, and reload; rollback requires restoring the complete backup.
- `Episode` has no owner field; all episodic-memory reads and mutations require `AuthorizationScope`, and the capability exposes counted scope and strict timestamp-cutoff deletion.
- Episodic-memory v1 record events contain owner-free episodes and their computed embeddings. Files use `episodic/<identity-sha256>.jsonl`, and ADO stream names use `episodic/<identity-sha256>`, computed with `AuthorizationIdentity.storageKey`. There is no reader for the previous shared `episodic.jsonl` file or `episodic` ADO stream. Reset disposable development state, or externally transform retained events using verified complete ownership identities and matching embeddings. The built-in reference embedding uses deterministic SHA-256 word buckets; old process-dependent hashes must not be mixed with it. Validate scoped queries, links, synthesis, deletion, and reload without embedding-provider callbacks. Rollback requires restoring the complete backup.
- `GraphNode` and `GraphRelation` have no ownership fields. Every `GraphMemory` operation requires `AuthorizationScope`; graph queries and mutations use its complete identity partition, relation removal is effective, and node deletion cascades incident relations.
- Graph-memory file and ADO.NET streams contain version-1 owner-free event envelopes with durable node, relation-batch, scope-deletion, and cutoff tombstones. Files use `graph/<identity-sha256>.jsonl`, and ADO stream names use `graph/<identity-sha256>`. Compute the key using `AuthorizationIdentity.storageKey`; never infer missing lineage from an old owner string. There is no reader for the previous shared `graph.jsonl` file or `graph` ADO stream. Reset disposable development state, or externally transform retained events using independently verified complete ownership identities before deploying. Validate scoped traversal, extraction, deletion, and restart; rollback requires restoring the whole backup rather than mixing layouts.
- `TieredMemoryEntry` has no owner field; every retrieval, access recording, promotion, capacity, eviction, and deletion operation requires `AuthorizationScope`. Retrieval does not mutate records implicitly, and eviction requires an effective time. Promotion does not widen the authorization partition.
- Tiered-memory v1 events use `tiered/<identity-sha256>.jsonl` files and `tiered/<identity-sha256>` ADO streams with explicit access/eviction times and durable deletion tombstones. Compute the key using `AuthorizationIdentity.storageKey`; owner-free events include the full `TieredMemoryConfig` replay policy. Reset disposable development state, or externally transform retained events using independently verified ownership identities and the original capacity/promotion/TTL configuration. Existing shared `tiered.jsonl` files and `tiered` streams have no compatibility reader. Changing the configured replay policy requires an explicit external state transformation or reset, not restamping old events. Validate capacity, promotion, TTL boundaries and scoped reloads; rollback requires restoring the complete backup.
- `MetricsCollector` accepts owner-free `MetricRecord` values with stable identity, timestamp, correlation, and typed payload. Recording, aggregation, cost estimation, execution lookup, and retention require the host-authenticated `AuthorizationScope`.
- Metrics file and ADO.NET streams contain version-1 accepted-record events and durable scope and strict timestamp-cutoff tombstones. Streams are partitioned as `metrics/<identity-sha256>` from the claim-free authorization identity. Aggregates are rebuilt from retained records, and duration is derived from accepted timestamps rather than collector lifetime.
- `FeedbackService` now exposes session-turn deletion through its owning facade.
- Session deletion coordinates conversation, turn, memory, metric, and execution-journal cleanup. Owner deletion returns the first structured failure and leaves directory/runtime identity intact for retry.
- `EvalDataset`, `EvalRun`, `EvalResult`, and `EvalReport` now require stable identity and explicit owner correlation. Runner APIs require a run identity for standalone cases and propagate one run through dataset reports.
- `EvalArchive` provides in-memory and version-1 JSONL persistence for datasets and reports, including owner and strict timestamp-cutoff tombstones. No ownerless evaluation archive format is accepted.
- Provider failures are no longer returned as `CompletionResult` values with `FinishReason = "error"`. Malformed output, HTTP failures, timeouts, and transport failures raise `PlatformFailureException` with the canonical category and retryability.
- Orleans host operations preserve structured harness, storage, and lifecycle failures instead of converting them to display strings or `InvalidOperationException`.

## Upgrade action

Development deployments must delete existing `nao_journal`, `nao_execution_journal`, `nao_feedback_turns`, and `nao_feedback_entries` tables and old `execution-journal.json`, `harness-checkpoints.json`, `tool-side-effects.json`, `turns.jsonl`, `feedback.jsonl`, `messages.json`, `meta.json`, `conversations.json`, `working.jsonl`, `episodic.jsonl`, `graph.jsonl`, `tiered.jsonl`, and `metrics.jsonl` files, plus previous unpartitioned ADO.NET streams, before running the new version. Nao is unreleased, so no compatibility reader or retained-data migration is provided.

No old record is assigned an inferred owner. Re-imported records must be transformed explicitly into the current schema with trustworthy owner and identity values.
